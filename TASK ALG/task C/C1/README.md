# Код-ревью: Модуль «Курьер»

## Анализ исходного кода
В исходном шаблоне была реализована базовая структура цикла `while True` с обработкой команд. Однако ключевые логические элементы — вычитание энергии при шаге, вывод текущего заряда при команде "заряд" и обработка неизвестной команды — были заменены пропусками.

## Выявленные ошибки и несоответствия
1. **Отсутствует логика вычитания энергии:** Стоял пропуск `energy = ________` в блоке `elif cmd == "шаг":`. Без этого робот не тратил бы заряд при движении.
2. **Отсутствует вывод заряда при команде "заряд":** Стоял пропуск `print("Заряд:", ________)` в блоке `elif cmd == "заряд":`. Без этого пользователь не видел бы результат пополнения энергии.
3. **Отсутствует обработка неизвестной команды:** Стоял пропуск `print(________)` в блоке `else:`. Без этого программа никак не реагировала бы на неверный ввод.

## Внесенные исправления
В соответствии с ТЗ (строки 01-11) были заполнены все пропуски:
- **Строка 04 (шаг):** Вставлено `energy - 2`. Согласно ТЗ, команда "шаг" вычитает 2 единицы заряда.
- **Строка 09 (заряд):** Вставлено `energy`. Согласно ТЗ, после пополнения (с учетом ограничения в 10) программа должна напечатать текущий заряд.
- **Строка 10 (else):** Вставлено `"Не понял"`. Согласно ТЗ, любая другая фраза должна вызывать именно это сообщение, не меняя заряд.

## Проверка по тестовым примерам
Код успешно проходит все сценарии из ТЗ:
- Ввод `шаг`, `шаг`, `стоп` -> Вывод `Заряд: 8`, `Заряд: 6`, `Итог: 6`
- Ввод `шаг` (5 раз) -> Вывод `Заряд: 8`, `Заряд: 6`, `Заряд: 4`, `Заряд: 2`, `Сел`
- Ввод `заряд`, `заряд` -> Вывод `Заряд: 10` (оба раза, так как 10+3=13, но ограничение ставит 10)
- Ввод `привет` -> Вывод `Не понял`

## Замечания по стилю
Использование `break` в блоках `if` корректно прерывает цикл при команде "стоп" или при разряде батареи. Логика ограничения заряда (`if energy > 10: energy = 10`) реализована верно. Код полностью соответствует алгоритму.
