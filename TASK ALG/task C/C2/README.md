# Код-ревью: Модуль «Сейф»

## Анализ исходного кода
В исходном шаблоне была реализована базовая структура цикла `while tries > 0` с проверкой кода. Однако ключевые логические элементы — вывод сообщения при успешном вводе и уменьшение счетчика попыток — были заменены пропусками.

## Выявленные ошибки и несоответствия
1. **Отсутствует вывод при успешном вводе:** Стоял пропуск `print(________)` в блоке `if code == secret:`. Без этого пользователь не получал бы подтверждения открытия сейфа.
2. **Отсутствует уменьшение счетчика попыток:** Стоял пропуск `tries = ________` после блока `if`. Без этого цикл был бы бесконечным при неверном вводе, так как `tries` всегда оставалось бы равным 3.

## Внесенные исправления
В соответствии с ТЗ (строки 01-09) были заполнены все пропуски:
- **Строка 05 (Открыт):** Вставлено `"Открыт"`. Согласно ТЗ, при совпадении кода с секретом программа печатает это слово и выходит из цикла (`break`).
- **Строка 07 (уменьшение попыток):** Вставлено `tries - 1`. Согласно ТЗ, при неверном вводе количество попыток уменьшается на единицу.
- Логика проверки `if tries == 0` и вывода `"Закрыт"` / `"Осталось:"` уже была корректна в шаблоне и не требовала изменений.

## Проверка по тестовым примерам
Код успешно проходит все сценарии из ТЗ:
- Ввод `421` -> Вывод `Открыт`
- Ввод `111`, `421` -> Вывод `Осталось: 2`, `Открыт`
- Ввод `111`, `222`, `333` -> Вывод `Осталось: 2`, `Осталось: 1`, `Закрыт`
- Ввод `123`, `456` -> Вывод `Осталось: 2`, `Осталось: 1`

## Замечания по стилю
Сравнение кода происходит как строк (`code == secret`), что соответствует ТЗ (строка 08). Преобразование в `int` не используется, что позволяет корректно обрабатывать ввод с ведущими нулями (например, `"0421"` не будет ошибочно принят за `421`).
